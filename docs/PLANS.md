# 計画の書き方

大きめの変更（複数のファイルにまたがる変更や、振る舞いを変える変更）は、着手の前に計画を書く。
計画は `docs/exec-plans/` の下に、`YYYY-MM-DD-<名前>.md` の名前で置く。

## 必須の節

計画には、次の 8 つの見出しを、この文字列のまま置く。書くことがまだ無い節も、見出しは残す。

1. `## 作業の場所`: 作業するブランチの名前。パスは書かない。
2. `## 目的`: 何を、なぜ変えるか。
3. `## 検証（完了の条件）`: 終わったと言える条件と、その確かめ方（試験の名前や、実行するコマンド）。
4. `## 手順`: 作業の順序。
5. `## 進捗`: 終えた手順と日付、残っている手順。
6. `## 発見`: 作業の途中で分かった、前提と違う事実。
7. `## 判断の記録`: 途中で決めたことと、その理由。
8. `## 結果と振り返り`: 閉じるときに、何ができて何が残ったかを書く。

## 検証の節の書式

次の日付以降に書く計画は、検証の節に、基準ごとの見出しと確かめ方の行を置く。

新しい書式の適用開始: 2026-10-09

- 基準ごとに `### V<数字> <題>` の見出しを置く。
- 見出しの下に `- 確かめ方: <試験の名前やコマンド>` の行を 1 つ置く。
